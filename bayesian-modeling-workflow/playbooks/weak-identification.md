# Weak identification

Read [priors](../references/prior-workflow.md), [simulation](../references/simulation.md) and relevant [latent](../references/latent-variable-models.md)/[geometry](../references/computational-diagnostics.md) guidance.

Observe a ridge, prior-like posterior, unstable component recovery, extreme coefficients or sensitivity. Check likelihood use, design rank/predictor variation, scale/support, parameter symmetries, joint predictions and MC reliability. Simulate several realistic truths and increase information to distinguish a code failure from limited design information.

Find identifiable scientific functions: combined curve, total signal, treatment contrast or prediction may be better informed than each nonlinear component. Remove accidental redundancy; anchor conventional location/scale; regularize with defensible information; simplify or gather calibration data when necessary. Strong priors are substantive assumptions, not recovered data information.

Validate known-data behavior, prior observables, computation, task PPC and sensitivity. Report predictive usefulness separately from limited parameter interpretation. Do not interpret a narrow posterior created by a hard identifying prior as proof the data learned the mechanism.
